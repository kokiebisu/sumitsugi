## 1. プロジェクト概要

### 1.1 プロジェクト名

**tsumugi（紡ぎ）**

### 1.2 コンセプト

暮らしを引き継ぐプラットフォーム

### 1.3 サービス概要

単なる物件のサブリースではなく、**家具・インテリア・ライフスタイルそのもの**を引き継ぐサービス。前の住人が築いた暮らしを次の住人へ繋ぐことで、空間の価値を最大化する。

---

## 2. 目的と背景

### 2.1 課題

- 引越し時の家具・インテリアの処分問題
- 理想的な空間探しの難しさ
- 短期〜中期の住まい探しの選択肢の少なさ

### 2.2 解決策

- 家具・インテリア付きの物件をそのまま引き継げる仕組み
- 前の住人のライフスタイルを可視化し、マッチングを促進
- 1〜6ヶ月の短期〜中期契約に対応

### 2.3 目標

- 暮らしを引き継ぐ人同士のコミュニティ形成
- 持続可能な暮らしの提案
- 空間の価値の最大化

## 4. ユーザー種別

### 4.1 ユーザーモデル（Airbnb風）

全ユーザーは入居希望者として登録し、暮らしを譲る側の登録で`isSeller=true`に切り替わる統一モデル。

**User（基本属性）**:

- id: UUID形式
- email: メールアドレス
- name: 氏名
- phone: 電話番号
- avatarUrl: プロフィール画像URL（任意）
- createdAt: 作成日時
- authProvider: 認証プロバイダー（email/google/facebook/apple）
- emailVerified: メール確認済みフラグ
- isSeller: セラーフラグ
- sellerProfile: セラープロフィール（isSeller=trueの場合のみ）

### 4.2 前の住人（Seller）

セラー登録済みのユーザー（`isSeller=true`）。自分の物件をリスティングできる。

**重要:** セラー登録済みのユーザーも、他の物件では次の住人として暮らしを引き継ぐことができる。「前の住人」「次の住人」はロールであり、ユーザーの固定的な分類ではない。

**SellerProfile（前の住人プロフィール）**:

- occupation: 職業
- bio: 自己紹介
- socialLinks: SNSリンク（Instagram, Twitter, YouTube, TikTok, Website）
- yearsSelling: 活動歴（年数）
- sellerSince: セラー登録日

**Phase 2以降で実装予定:**

- rating: 評価（1-5）
- reviewCount: レビュー数

### 4.3 次の住人

暮らしを引き継ぐ側のユーザー。**すべてのユーザー**（`isSeller`の値に関わらず）が次の住人として物件に問い合わせできる。セラー登録済みのユーザーも、自身が登録した物件以外では次の住人として活動できる。

### 10.5 大家承認バッジ

物件の信頼性を可視化し、次の住人に適切な期待値を伝えるバッジシステム:

**バッジ表示（物件カード）**:

- `landlordConsent: true` → 緑のチェックマーク「✓ 承認済」
- `landlordConsent: false` → 表示なし or グレーの「要確認」

**バナー表示（物件詳細ページ上部）**:

承認済みの場合（緑色バナー `bg-green-50 border-green-200`）:

```
┌─────────────────────────────────────────────┐
│ ✓ 大家承認済み                               │
│ 入居までスムーズに進む可能性が高いです       │
└─────────────────────────────────────────────┘
```

未承認の場合（黄色バナー `bg-yellow-50 border-yellow-200`）:

```
┌─────────────────────────────────────────────┐
│ ℹ️ 大家承認は未取得です                       │
│ 問い合わせ後、大家への確認が必要です。       │
│ 承認取得までお時間をいただく場合があります。 │
└─────────────────────────────────────────────┘
```

**表示位置**:

- 物件詳細ページ: 画像ギャラリーの下、問い合わせボタンの近く
- 物件カード: タイトル付近に小さなバッジとして表示

## 11. 引き継ぎフロー

物件の引き継ぎは以下の7ステップで行われる:

1. **物件登録・公開** - 前の住人が物件情報を登録し公開（大家承認は任意、後から追加可能）
2. **問い合わせ** - 次の住人からの問い合わせ受付
3. **大家承認取得**（任意）- 問い合わせ後、必要に応じて大家に相談・承認取得
4. **内見調整** - 内見日程の調整
5. **内見実施** - 実際の物件見学
6. **契約** - 賃貸契約の締結、引越し費用の支払い
7. **引き継ぎ** - 物件・ライフスタイルの引き継ぎ完了

### 大家承認について

- 物件登録時に大家承認は必須ではない（`landlordConsent: false`でも公開可能）
- 大家承認済みの物件（`landlordConsent: true`）には「✓ 大家承認済み」バッジが表示される
- 問い合わせを受けた後、具体的な入居希望者がいる状態で大家に相談することも可能
- 物件詳細ページでは、大家承認の有無に応じてバナーを表示し、次の住人に期待値を伝える

## 12. 決済システム

### 12.1 概要

tsumugiの決済システムは、次の住人から前の住人・大家・管理会社への複数者間の資金分配を安全かつ自動的に処理します。

### 12.2 決済プロバイダー

- **Stripe Connect**: エスクロー機能を活用した多者間決済を実現

### 12.3 引越し費用の構成

次の住人が支払う「引越し費用」の内訳（ユーザーには一括表示）:

```
引越し費用 = 追加清掃費 + 前の住人への支払い + 大家協力金 + プラットフォーム手数料
```

**金額例（引越し費用 ¥150,000 の場合）:**
- 追加清掃費: ¥8,000（固定額）
- 大家協力金: ¥3,000（引越し費用の1%、最低保証¥3,000）
- プラットフォーム手数料: ¥22,500（15%）
- 前の住人受取: ¥116,500

### 12.4 支払いフロー

#### 1. 申込金（¥20,000）

内見後、賃貸審査申し込み時に支払い:
- **金額**: ¥20,000（固定額）
- **性質**: 非返金
- **分配**: 即座にStripe Transferで前の住人へ
- **目的**: 前の住人の機会損失補償、次の住人のコミットメント確保

#### 2. デポジット（30%）

賃貸審査通過・契約締結後に支払い:
- **金額**: 引越し費用の30%（最低¥30,000、最高¥50,000）
- **性質**: 返金可能（キャンセルポリシーに基づく）
- **保管**: Stripe Connect でエスクロー保管

#### 3. 残額（70%）

引き継ぎ日確定時に支払い:
- **金額**: 引越し費用の70%
- **性質**: 返金可能（キャンセルポリシーに基づく）
- **保管**: Stripe Connect でエスクロー保管

#### 4. エスクロー解放

引き継ぎ完了後、双方が「完了」確認:
- **待機期間**: 24-48時間（異議申し立て期間）
- **自動分配**: 前の住人・大家・管理会社へ自動送金

### 12.5 キャンセルポリシー

**申込金支払い後のキャンセル:**
- 次の住人都合: 申込金¥20,000は返金なし（前の住人が保持）
- 前の住人都合: 申込金¥20,000は全額返金
- 審査落ち: 申込金¥20,000は返金なし（前の住人への補償）

**デポジット/残額支払い後のキャンセル:**
- 次の住人都合: デポジット没収（前の住人への補償）
- 前の住人都合: デポジット・残額 全額返金
- 双方合意: デポジット・残額 全額返金

### 12.6 データモデル拡張

決済システム実装のため、以下のテーブルが必要:

**Payment（支払い）:**
- `id`: 支払いID
- `propertyId`: 物件ID
- `userId`: 支払者ID（次の住人）
- `type`: 支払い種別（`application_fee` | `deposit` | `remaining`）
- `amount`: 支払い総額
- `stripePaymentIntentId`: Stripe PaymentIntent ID
- `status`: ステータス（`pending` | `succeeded` | `failed` | `refunded`）
- `createdAt`: 作成日時

**Transaction（分配ログ）:**
- `id`: 取引ID
- `paymentId`: 支払いID
- `recipientType`: 受取人種別（`previous_tenant` | `landlord` | `property_management` | `platform`）
- `recipientId`: 受取人ID
- `amount`: 分配金額
- `stripeTransferId`: Stripe Transfer ID
- `status`: ステータス（`pending` | `succeeded` | `failed`）
- `createdAt`: 作成日時

**StripeAccount（Stripe Connect アカウント）:**
- `id`: アカウントID
- `userId`: ユーザーID
- `stripeAccountId`: Stripe Connect Account ID
- `accountType`: アカウント種別（`previous_tenant` | `landlord` | `property_management`）
- `onboardingCompleted`: オンボーディング完了フラグ
- `createdAt`: 作成日時
