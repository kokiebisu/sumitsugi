## MVP（最小リリーススコープ）

> プロダクトミーティング（2026-02-06〜07）にて全ペルソナ合意。
> 選定基準：「初めて使う人が信頼できる最小限」
>
> **コンシェルジュ型MVP方針（座談会#10で確定）：**
> 最初の数件は運営がユーザーとつきっきりで進める前提。自動化（リマインド通知・期限切れ処理等）は
> 手動運用でデータを収集してから実装する。手動でしか得られない「最適なタイミング・文面」の知見が自動化の品質を決める。
>
> **信頼の連鎖（ペルソナ合意の核心）：**
> 承認バッジの機能を作っても、承認を取るための資料がなければバッジは永遠に「未承認」。
> 次の住人は不安になり問い合わせしない。前の住人にも問い合わせが来ない。誰も使わない。
> → B2B信頼インフラ（PDF自動生成・使い方ガイド）はMVP必須。

**コア機能：**

- 物件情報の表示（一覧・詳細・画像ギャラリー・テイスト検索・暮らしストーリー）
- 物件登録・管理機能（新規登録・編集・ステータス管理）
- 問い合わせフォーム + 問い合わせ一覧（シンプルなリスト表示）
- 基本的な認証機能（サインアップ・ログイン・ログアウト・セラー化）
- アカウント機能（プロフィール表示・編集）
- 大家承認ステータス表示（バッジ・バナー）
- 退去日フィールド + 最低猶予期間チェック（F-501, F-502）

**決済インフラ（2026-02-06 追加、座談会#10で簡略化）：**

- Stripe Connect（Destination Charges）最低限実装 — tsumugiが資金を預からない安全な決済基盤
  - 前の住人のStripe Connectedアカウント作成・オンボーディング
  - 引越し費用の決済（**2段階**: 申込金¥20,000 → 残額一括）— 座談会#10でハル・ケンジの「3段階は混乱する」意見を受け簡略化
  - エスクロー解放はMVPでは管理者が手動トリガー
  - 分配先：前の住人（Destination）、大家・管理会社・プラットフォーム（Transfer）

**信頼・安心感インフラ（2026-02-06 追加、座談会#10で整理）：**

- 使い方ガイドページ（F-701）— 問い合わせ〜入居の9ステップを図解
- PDF自動生成（F-611, F-612）— リスティングデータから2段階で自動生成
  - 出品時：残置物引き継ぎ相談資料（F-611）— 暫定家具リスト
  - 内見後・家具リスト確定時：残置物同意書（F-612）— 確定家具リスト＋署名欄
  - **PDF品質要件：** 管理会社が読むだけで完結する自己完結型
  - ~~仲介向け物件シート（F-616）~~ → **Post-MVP**（座談会#10: 最初はF-611経由で管理会社→仲介に伝達）
- 管理会社向けFAQ（F-615）— 静的ページ
- 問い合わせ受付自動通知メール（F-204）— 問い合わせ送信時の確認メール
- ~~承認リマインド通知（F-205）~~ → **Post-MVP**（座談会#10: 運営が手動プッシュ。最適なタイミング・文面のデータを収集してから自動化）
- ~~承認期限切れ自動処理（F-206）~~ → **Post-MVP**（座談会#10: 最初の数件は手動対応）
- 簡易メッセージ機能 — tsumugi画面上でテキスト送受信・日程調整テンプレート・メール通知・スレッド管理。個人メアド非公開。詳細は[座談会#8議事録](../meetings/2026-02-07-product-meeting-8-viewing-flow.md)参照
- 値付けガイダンス — 出品時の使用年数×新品価格による目安レンジ表示、次の住人への比較情報（[data-model.md §7.10](./data-model.md#710-値付けガイダンス座談会9で決定)参照）

## Phase 1 Post-MVP（MVP後に段階的追加）

MVPリリース後、利用実績に応じて段階的に追加する機能群。最初の数件は手動対応で代替可能と全ペルソナが合意。コンシェルジュ型MVP（運営つきっきり）で得た知見を元に自動化を進める。

- 決済システムの自動化拡張（エスクロー自動リリース、分配ダッシュボード、返金自動処理）→ MVPではStripe Connectの最低限実装で開始
- **決済の3段階化**（申込金→デポジット→残額）→ MVPでは2段階（申込金→残額一括）で開始。キャンセル率のデータを見てから分離（座談会#10）
- **承認リマインド通知（F-205）** → 運営が手動プッシュでデータ収集してから自動化（座談会#10）
- **承認期限切れ自動処理（F-206）** → 最初の数件は手動対応（座談会#10）
- **仲介向け物件シート（F-616）** → 管理会社経由で仲介に伝達。仲介との接点が増えてから（座談会#10）
- **問い合わせステータスの画面表示** → データモデルは8段階保持、ユーザー向け進捗表示はメッセージで手動案内。取引数が増えてから画面実装（座談会#10）
- B2B連携の残り（紹介フィー F-601, 残置物チェックリスト F-613, 日程調整テンプレート F-614）→ 最初は人力対応
- B2Bテック自動化（F-602〜F-607）→ 物件数が増えてから
- 引き継ぎフロー可視化の残り（ステップインジケーター F-711〜F-712, 支払いタイムライン F-713, 費用の仕組み説明 F-702, 所要期間の目安表示 F-703）→ 手動案内で代替
- 段階的通知（退去日アラート F-503〜F-506）→ 物件数が増えてから
- マッチング促進（即入居ラベル, 入居可能日フィルター F-507〜F-508）→ 物件数が増えてから
- 最終手段（緊急引き取り案内, 処分業者リスト F-509〜F-511）→ 手動対応で代替
- 内見負担軽減（FAQ機能, 内見承認制 F-801〜F-804）→ 問い合わせフォームで代替
- 問い合わせステータス管理画面（F-203）→ 取引数が増えてから
