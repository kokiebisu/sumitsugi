## 結論

**Phase 1のMVP機能で柏の葉デモは十分に実施可能。**

現在の実装で、物件一覧・物件詳細・出品フロー・問い合わせ・使い方ガイド・管理会社向けFAQの一連のフローがデモ可能。
追加開発なしで、sumitsugiの価値提案（退去時の家具廃棄問題を解決する循環型プラットフォーム）を説明できる。

## 2. 推奨デモフロー

### シナリオ: 「退去する住人が、暮らしを次の住人に引き継ぐ」

**想定時間:** 10-15分

#### Part 1: 次の住人の体験（3-4分）

1. **ホームページ** (`/`)
   - エリア別の物件表示を見せる
   - 入居可能月フィルターで絞り込みデモ
   - 「Airbnbのように物件を探せる」と説明

2. **物件詳細** (`/listings/[id]`)
   - サンプル物件（例: 「アートと植物に囲まれたワンルーム」id: `1368794573069214647`）を選択
   - 画像ギャラリーのスワイプ操作
   - 引き継ぎ対象家具の2層表示（コアセット / 追加家具）
   - 値付けガイダンス（新品購入との比較）
   - 大家承認バッジ（緑「大家承認済み」）
   - 前の住人のストーリー・メッセージ
   - 地図表示

3. **問い合わせフォーム** (`/listings/[id]/inquiry`)
   - 「この暮らしに興味があります」と問い合わせを送信

#### Part 2: 前の住人の体験（3-4分）

4. **使い方ガイド** (`/guide`)
   - 引き継ぎ9ステップの全体像を説明
   - 前の住人向け/次の住人向けの切り替え表示

5. **物件新規登録** (`/listing/new`)
   - 家具選択UI（チェックボックス形式）
   - 値付けガイダンス（使用年数 x 新品価格で目安レンジ表示）
   - 位置情報ピッカー（地図上で物件位置を設定）
   - 退去日設定

6. **リスティング管理** (`/listing`)
   - ダッシュボード表示（リスティング一覧 + 問い合わせタブ）
   - 大家承認ステータスの表示

7. **残置物相談資料PDF** (`/listing/[id]/pdf`)
   - 管理会社向けPDFの自動生成を見せる
   - 「このPDFを管理会社に送るだけ」と説明

#### Part 3: 管理会社（B2B）の体験（2-3分）

8. **管理会社向けFAQ** (`/for-managers`)
   - 管理会社が「これは何？」と思ったときの説明ページ
   - 従来の残置物処理との比較

9. **使い方ガイド**で全体の流れを再確認
   - 管理会社の関与ポイントを強調

#### Part 4: まとめ（1-2分）

10. **ホームページ**に戻り、物件数（35件以上のサンプル）を見せて規模感を伝える
    - 「柏の葉エリアの物件を追加すれば、すぐにこの形でサービス開始できる」

## 3. デモデータ（シードデータ）の状況

### 現在のシードデータ

- **物件数:** 35件以上（東京中心 + 大阪・湘南・京都・福岡・札幌・名古屋・沖縄）
- **データの充実度:** 各物件に以下が含まれる
  - タイトル、サマリー、ストーリー（暮らしの物語）
  - 画像（5枚前後、外部URL）
  - 家具リスト（コアセット/追加家具の2層構造）
  - 引越し費用、家賃、管理費、敷金・礼金
  - 位置情報（緯度・経度、最寄り駅エリア）
  - 退去予定日
  - 大家承認ステータス（approved, conditional, pending等）
  - 前の住人プロフィール（職業、自己紹介、こだわりポイント3つ）
  - 家具の状態（excellent, good, used）

### デモ向けデータの推奨事項

| 項目                         | 現状        | 推奨対応                                               |
| ---------------------------- | ----------- | ------------------------------------------------------ |
| 柏の葉エリアの物件           | なし        | **デモ前に2-3件追加推奨**（三井不動産への訴求力向上）  |
| 柏の葉テーマの物件ストーリー | なし        | 「スマートシティで環境配慮型の暮らし」ストーリーを作成 |
| 管理会社名の設定             | 一部未設定  | デモ物件には「三井不動産レジデンシャル」等を設定       |
| 画像                         | 外部URL依存 | デモ当日のオフライン対策としてR2バケットへの移行を検討 |

## 4. ギャップ分析（デモに影響する未実装機能）

### デモに影響なし（コンシェルジュ型MVPとして説明可能）

| 機能                   | 状態               | デモでの対応                                                                |
| ---------------------- | ------------------ | --------------------------------------------------------------------------- |
| メッセージ機能         | プレースホルダー   | 「MVP初期は運営がつきっきりで対応。自動化は利用データを収集してから」と説明 |
| 決済（Stripe Connect） | プレースホルダー   | 「決済基盤は開発中。初期は手動で対応し、安全性を確保」と説明                |
| 承認リマインド通知     | 未実装（Post-MVP） | 「運営が手動プッシュ。最適なタイミングのデータを収集中」と説明              |
| 電子契約               | 対象外（Phase 2）  | 賃貸契約は管理会社の既存フローを使用                                        |

### デモ当日の注意事項

| リスク             | 対策                                                                                                   |
| ------------------ | ------------------------------------------------------------------------------------------------------ |
| ネットワーク不安定 | サンプルデータはローカルの`data.ts`に内蔵されているため、API未接続でもホームページ・物件詳細は表示可能 |
| 画像読み込み遅延   | 外部URL（Unsplash等）依存のため、事前にブラウザキャッシュを温めておく                                  |
| DB接続不要         | 静的データ（data.ts）とクライアントサイドの状態管理で基本フローは動作                                  |
| 認証不要のデモ     | ホーム・物件一覧・物件詳細・ガイド・管理会社FAQは未ログインでも閲覧可能                                |

## 6. 結論と推奨アクション

### 結論

現在の実装（Phase 1 MVP）で、柏の葉デモに必要な全ての画面・フローが揃っている。
コンシェルジュ型MVP方針（運営つきっきり）の説明と合わせれば、プレースホルダー状態の機能も
「意図的にデータ収集を優先している」とポジティブに説明可能。

### デモ前の推奨アクション

| 優先度 | アクション                                      | 工数    | 担当     |
| ------ | ----------------------------------------------- | ------- | -------- |
| **高** | 柏の葉エリアのサンプル物件を2-3件追加           | 1-2時間 | dev      |
| **高** | デモ用アカウントの事前作成（前の住人/次の住人） | 30分    | dev      |
| **中** | デモ手順のリハーサル（10-15分のフロー確認）     | 1時間   | 全員     |
| **中** | 画像のR2バケット移行（オフライン対策）          | 2-3時間 | dev      |
| **低** | 柏の葉テーマのストーリーテキスト作成            | 1時間   | business |
| **低** | デモ用の管理会社名設定                          | 15分    | dev      |

### 備考

- 追加開発は不要。データ準備とリハーサルのみで十分
- コンテスト応募締切を確認次第、逆算でデータ準備スケジュールを組む
- 応募資料のフレーミング: 「退去時の家具廃棄問題をスマートシティで解決する循環型プラットフォーム」（CPO提案）
