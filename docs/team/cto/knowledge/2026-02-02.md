## React Server Components & Streaming（RSC・ストリーミング）

## API Design: REST vs GraphQL vs tRPC（API設計）

- [2026 API Landscape](https://dev.to/dataformathub/rest-vs-graphql-vs-trpc-the-ultimate-api-design-guide-for-2026-8n3) - **共存と専門化**。REST=公開API、GraphQL=複雑UI、tRPC=TypeScriptモノレポ
- [tRPC for Next.js](https://www.pedroalonso.net/blog/nextjs-apis-with-trpc/) - **GraphQL級の型安全性+RESTのシンプルさ**。スキーマ不要、コード生成不要、ランタイムオーバーヘッドなし。TypeScriptの型システムでコンパイル時エラー検出
- [When to Use Each](https://caisy.io/blog/when-to-use-trpc-or-graphql) - **内部TypeScriptフルスタック→tRPC、複数言語クライアント→REST、データ要求が可変→GraphQL**。sumitsugiは内部APIにtRPC、公開API (将来) にREST
- [tRPC Best Practices](https://sdtimes.com/graphql/trpc-vs-graphql-vs-rest-choosing-the-right-api-design-for-modern-web-applications/) - プロシージャを集中・明示的型付け。Zodでバリデーション。ルーター型をクライアントにエクスポート。ドキュメント維持
