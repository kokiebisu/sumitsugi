## 3. 日本のビジネスコンテストにおける一般的なIP条項パターン

公開情報が不十分なため、日本国内のビジネスアイデアコンテストで一般的に使用されるIP条項のパターンを整理し、各パターンにおけるtsumugiへのリスクを評価する。

### パターンA: 著作権譲渡型（高リスク）

> 「入賞作品の著作権（著作権法第27条及び第28条の権利を含む）は主催者に帰属する」

- **リスク評価: 高**
- 入賞した場合、応募資料に記載した事業アイデアの表現物（企画書、プレゼン資料等）の著作権が主催者に移転
- ただし、著作権法上「アイデア」そのものは著作権の保護対象外であることに留意

### パターンB: 利用許諾型（中リスク）

> 「主催者は入賞作品を広報・報告等の目的で使用する権利を有する」

- **リスク評価: 中**
- 著作権自体は応募者に帰属するが、主催者が一定範囲で利用可能
- 利用範囲の広さにより実質的な影響度が変動

### パターンC: 応募者帰属型（低リスク）

> 「提案内容および発表資料に関する著作権ならびにその他の知的財産権は応募者に帰属する」

- **リスク評価: 低**
- 近畿経済産業局の知財ビジネスアイデアコンテスト等で採用されている形式
- 応募者の権利が最も保護される

### パターンD: 著作者人格権不行使型（中〜高リスク）

> 「応募者は著作者人格権を行使しないものとする」

- **リスク評価: 中〜高**
- 著作権帰属とセットで規定されることが多い
- 主催者による改変・二次利用が自由になる

## 4. tsumugiへの影響分析

### 4.1 保護すべきtsumugiの知的財産

| 資産カテゴリ   | 具体的内容                                       | コンテストでの開示度           |
| -------------- | ------------------------------------------------ | ------------------------------ |
| ビジネスモデル | プラットフォーム手数料モデル、大家協力金スキーム | 応募資料に記載する可能性が高い |
| 技術実装       | Next.js/Stripe Connect構成、引き継ぎフローのUX   | 概要レベルのみ開示予定         |
| ソースコード   | プラットフォームのコードベース                   | 非開示（提出不要）             |
| ブランド       | tsumugiブランド、UI/UXデザイン                   | 企画書に記載                   |
| ユーザーデータ | なし（プレローンチ段階）                         | 非該当                         |

### 4.2 リスク分析

#### 重要な法的前提

**アイデアそのものは著作権法で保護されない。** 著作権法が保護するのは「表現」であり、ビジネスモデルのアイデア自体は著作権の対象外。したがって、仮にパターンA（著作権譲渡型）が適用されても、以下の区別が重要：

| 項目                       | 著作権譲渡の影響       | 備考                   |
| -------------------------- | ---------------------- | ---------------------- |
| 企画書・プレゼン資料の表現 | 影響あり（譲渡対象）   | 資料の文章・デザイン   |
| ビジネスモデルのアイデア   | 影響なし（保護対象外） | 自由に利用・実装可能   |
| ソースコード               | 影響なし（非提出）     | コンテストとは無関係   |
| 特許・実用新案             | 別途確認必要           | 規約に含まれる場合あり |

#### リスクシナリオ

**シナリオ1: 最悪ケース（パターンA + D適用時）**

- 応募資料の著作権が三井不動産側に帰属
- 資料に基づき類似サービスが開発される可能性（ただし、アイデアの保護は著作権では不可能）
- **tsumugiの既存ソースコード・実装には影響なし**
- **リスク評価: 中**（ビジネスモデルのアイデア自体は著作権で保護されないため）

**シナリオ2: 標準ケース（パターンB適用時）**

- 主催者による広報目的の利用のみ
- tsumugiのビジネスに実質的影響なし
- **リスク評価: 低**

**シナリオ3: 好ケース（パターンC適用時）**

- 全権利が応募者に帰属
- **リスク評価: 極低**

### 4.3 「共創パートナーマッチング」に関する留意点

コンテストのプロセスには「共創パートナー企業とのマッチング」が含まれる。これに伴い：

- マッチング時に追加のNDA（秘密保持契約）や共同開発契約の締結を求められる可能性
- パートナー企業との協業における知的財産の帰属条件が別途設定される可能性
- **これらの条件は応募規約とは別の契約として管理される可能性が高い**

## 5. 総合リスク評価

| リスク項目                 | 評価       | 理由                                                                           |
| -------------------------- | ---------- | ------------------------------------------------------------------------------ |
| IP条項が非公開であること   | **中**     | 応募前に条件確認が必須                                                         |
| 著作権譲渡の可能性         | **中**     | 一般的なコンテストでは入賞作品の著作権譲渡が多い                               |
| ビジネスモデル模倣リスク   | **低**     | アイデアは著作権法の保護対象外だが、コンテスト参加有無に関わらず存在するリスク |
| ソースコード・技術への影響 | **極低**   | 提出物に含まれないため影響なし                                                 |
| 共創パートナー契約リスク   | **要確認** | ファイナリスト選出後に発生する別契約                                           |

### 総合評価: **中リスク（条件付きで参加推奨）**

コンテスト参加自体のリスクは限定的だが、IP条項が非公開であるため、**応募前に必ず条件を確認する**必要がある。

## 6. 推奨アクション

### 即時対応（応募前）

1. **応募規約のIP条項を事務局に問い合わせる**
   - 問い合わせ先: info@hatsumeinoha.jp
   - 確認事項:
     - 応募作品の著作権帰属（応募者帰属 or 主催者帰属）
     - 入賞・非入賞による帰属の違い
     - 著作者人格権の取り扱い
     - 特許権・実用新案権等の知的財産権の帰属
     - 応募資料の主催者による二次利用の範囲
     - 共創パートナーマッチング時の追加契約条件

2. **回答内容を外部弁護士に確認**
   - 取得したIP条項の文言を外部弁護士に提示し、法的リスクの最終判断を仰ぐ
   - 無料法律相談（東京都中小企業振興公社等）の活用を推奨

### 応募時の対策

3. **応募資料の記載範囲をコントロールする**
   - 技術的な実装詳細は記載しない（概要レベルに留める）
   - Stripe Connect等の具体的な技術スタックは非開示
   - 収益モデルの詳細（手数料率等）は一般的な表現に留める
   - 差別化要因は「実行力」「ユーザー理解」に重点を置く

4. **既存の知的財産を事前に証拠化する**
   - GitHubのコミット履歴が既存のソースコードの先行開発の証拠となる
   - 応募前のビジネスモデル文書にタイムスタンプを確保（既にdocs/配下にGit管理済み）

### ファイナリスト選出時の対策

5. **共創パートナー契約の条件を慎重に確認する**
   - NDA（秘密保持契約）の範囲と期間
   - 共同開発の成果物に関するIP帰属
   - 独占条項の有無
   - → **外部弁護士への相談を強く推奨**
