# GTM Meeting: 営業・顧客獲得戦略会議

ペルソナの「顧客としての声」と経営陣の「戦略視点」を組み合わせて、**具体的に実行可能なビジネスプレイブック**を作る会議。

## Quick Start

**LANGUAGE: This meeting is ALWAYS conducted in Japanese.**

**When invoked, immediately:**

1. **Check for executive directives** (CRITICAL)
   - Read latest file in `docs/team/directives/gtm/`
   - Present directives to participants at meeting start
2. Read CMO strategy: `docs/team/cmo/STRATEGY.md`
3. Read CEO strategy: `docs/team/ceo/STRATEGY.md`
4. Read relevant persona files from `docs/team/personas/`
5. Read latest CMO/CEO knowledge files if they exist
6. Start the meeting

## Meeting Flow

## Input: 役員会議Directiveの読み込み

**GTM会議開始時に、役員会議からのDirectiveを確認する:**

```
docs/team/directives/gtm/YYYY-MM-DD-exec-N.md
```

**Directiveがある場合:**

- 最新のDirectiveを読み込み、CMOがミーティング冒頭でペルソナに共有する
- 獲得戦略の前提条件として反映する（例: 「CEOから友人紹介チャネルに集中の指示」）
- Directiveの指示事項を仮説の出発点とする

**Directiveがない場合:**

- 従来通り、CMOが独自の仮説を提示する

**CMOによるブリーフィング例:**

```
📣 CMO: 今日のテーマに入る前に、役員会議からの指示を共有します。
   - CEOから: 最初の2週間は友人紹介に集中する方針です
   - CFOから: 初期マーケティング予算はゼロ、オーガニックのみ
   この前提で、今日の仮説を組み立てています。
```

---

### Phase 1: CMO仮説提示（1-2 exchanges）

CMOが現在の獲得戦略の仮説を提示し、ペルソナに検証を求める。

```
📣 CMO: 今日のテーマは[X]です。
   現在の仮説として、[チャネルA]と[チャネルB]で[ターゲット]にリーチしようと考えています。
   まずユキさん、もし[チャネルA]で声をかけられたとしたら、率直にどう感じますか？
```

### Phase 2: ペルソナ検証（4-8 exchanges）

**ここがメイン。** ペルソナが「顧客として」CMOの仮説を検証する。

**ペルソナの発言テンプレート：**

- 「それ、私には**刺さる/刺さらない**。なぜなら...」
- 「私がそのチャネルを見るのは**こういう時**」
- 「こう言われたら**動く/動かない**」
- 「正直、**こっちのほうが**嬉しい」

**CMOはペルソナの声を受けて仮説を修正する。CEOは優先順位とリソースの制約を加える。**

ペルソナ同士のリアクション・ファーストルールは `meeting:product` と同様：

- 他のペルソナの発言に**必ずリアクションしてから**自分の意見を言う
- 対立は歓迎（「ユキさんはそうかもだけど、僕みたいな転勤族は...」）

### Phase 3: アクション設計（2-4 exchanges）

CMO + CEOが議論を踏まえて、具体的なアクションプランを設計。ペルソナは最終チェック。

```
📣 CMO: 議論を踏まえて、アクションプランを整理します。
   [チャネル]で[ターゲット]に[メッセージ]でアプローチ。
   具体的なステップは...

🎯 CEO: リソース面を加えると、最初の2週間は[X]に集中して、
   [Y]は次のフェーズで。

🏠 ユキ: そのメッセージなら、私は動きます。一点だけ、[修正提案]。
```

### Phase 4: プレイブック生成

議論の結果を**ビジネスプレイブック**として構造化。

## Discussion Rules

### Rule 1: ペルソナは「証言者」

ペルソナ座談会では製品機能について議論するが、GTM会議では**自分がどう発見され、どう動かされるかを証言する**。

```
# GOOD: 証言（GTM会議向き）
🏠 ユキ: 「私がインスタで引越し関連を検索するのは、引越しの2ヶ月前くらいから。
          その時に『家具捨てなくて済む方法』って出てきたら、絶対タップする」

# BAD: 機能要望（これはプロダクト会議向き）
🏠 ユキ: 「検索機能にフィルターがほしい」
```

### Rule 2: CMOは仮説を修正する勇気を持つ

ペルソナの声で仮説が否定されたら、素直に修正する。

```
📣 CMO: なるほど、ユキさんの声を聞くと[チャネルA]は効果薄そうですね。
   代わりに[チャネルC]を優先しましょう。理由は...
```

### Rule 3: CEOはリソース制約を守る

営業未経験のファウンダーが一人でやる前提。「やりたいこと」ではなく「できること」を選ぶ。

```
🎯 CEO: マリさんのコーディネーターネットワークは魅力的だけど、
   それは5件成約してからのフェーズ。今は友人紹介+SNSに絞りましょう。
```

### Rule 4: 「営業未経験でもできるか」チェック

全てのアクションに対して、以下を確認：

- 特別なスキルが不要か？
- 1回あたり30分以内で完了するか？
- テンプレートやスクリプトで再現可能か？
- 失敗しても致命的でないか？

## Example Meeting

### テーマ: 「最初の前の住人5人をどう見つけるか」

**参加者:** CMO、CEO、ユキ、ケンジ、トモヤ、マリ

---

📣 CMO: 今日のテーマは「最初の前の住人をどう見つけるか」です。
仮説として、まず3つのチャネルを考えています：
①友人紹介、②SNS（Xで引越し関連の投稿者にリプ）、③ジモティー出品者へのDM。
ユキさん、もし引越し予定で、Xに「家具どうしよう」って呟いた時に
知らないアカウントからリプが来たら、どう感じますか？

🏠 ユキ: 正直、**知らないアカウントからのリプは警戒**します。
でも、そのアカウントのプロフィールが
「家具を捨てずに次の人に引き継ぐサービスを作ってます」
って書いてあって、リプの内容も
「うちのサービス使ってください！」じゃなくて
「分かります、私も同じ経験があって...」だったら、
プロフィール見に行くかも。

⏰ ケンジ: ユキさんの話分かるけど、僕みたいに急いでる人間は
むしろ**直球で「解決策あります」って言ってほしい**。
共感の前置きより、「家具、捨てずに済みます。詳細→リンク」のほうが刺さる。

📣 CMO: 面白いですね。ターゲットの緊急度で**メッセージを分ける**必要がありそうです。
ユキさんタイプ（余裕あり）→ 共感型アプローチ
ケンジさんタイプ（急ぎ）→ ソリューション直球型

🎯 CEO: チャネルの優先順位として、最初の2週間は
①友人紹介に集中。ここで1-2件見つけられたら理想。
SNSとジモティーは並行して仕込むけど、工数の主力は①。
理由は、**信頼のコストがゼロ**だから。

🪑 マリ: CEOの「信頼のコスト」、プロとして同意です。
私がお客様にtsumugiを紹介する場合も、
**「マリさんが言うなら」の信頼が最初から乗ってる**。
ファウンダーが知り合い経由で行くのは正解。

📣 CMO: まとめると、プレイブックはこうなりますね...
[プレイブック生成に進む]
