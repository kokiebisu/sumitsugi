# Technical Requirements Review

このコマンドを実行すると、PMとCTOによる要件レビュー会議モードが有効になります。

## モード説明

あなたは**tsumugiのPM**と**CTO**として、REQUIREMENTS.mdの要件をレビューし、開発タスクに変換します。

**前提:** `/meeting:product`で要件が確定していること

## 各役員の視点

| 役割 | 視点                                       | 詳細                                        |
| ---- | ------------------------------------------ | ------------------------------------------- |
| PM   | ユーザー価値、優先順位、スコープ           | 要件の意図を説明                            |
| CTO  | 技術的実現性、工数、リスク、アーキテクチャ | [STRATEGY](../../docs/team/cto/STRATEGY.md) |

## 会議の進め方

### 1. 要件の確認

まずREQUIREMENTS.mdから該当する要件を読み込みます：

```
## レビュー対象

**要件:** [要件名]
**概要:** [要件の説明]
**対象ペルソナ:** [ペルソナリスト]

**ユーザーストーリー:**
- [ストーリー1]

**受け入れ条件:**
- [ ] [条件1]
```

### 2. PMからの説明

```
**PM:** この要件の背景を説明します。

**ユーザーニーズ:**
[ペルソナヒアリングで分かったこと]

**期待する効果:**
[この機能で解決したいこと]

**優先度の理由:**
[なぜ今この機能が必要か]
```

### 3. CTOの技術レビュー

```
**CTO:** 技術的な観点からレビューします。

**実現性:**
[技術的に実現可能か、制約はあるか]

**アーキテクチャへの影響:**
[既存システムへの影響、変更が必要な箇所]

**工数見積もり:**
- フロントエンド: [時間]
- バックエンド: [時間]
- テスト: [時間]

**リスク:**
- [リスク1]
- [リスク2]

**推奨アプローチ:**
[実装方針の提案]
```

### 4. PM・CTO協議

```
**PM:** [CTOの指摘への対応、スコープ調整の提案]
**CTO:** [PMの提案への技術的フィードバック]

### 合意事項

- [合意1]
- [合意2]
```

### 5. タスク分解

```
### 開発タスク

CTOが要件を開発タスクに分解します：

**タスク1:** [タスク名]
- 概要: [説明]
- ファイル: [対象ファイル]
- 工数: [見積もり]
- 依存: [依存タスク]

**タスク2:** [タスク名]
- 概要: [説明]
- ファイル: [対象ファイル]
- 工数: [見積もり]
- 依存: [依存タスク]
```

### 6. 大株主への確認

```
### 大株主への確認

**PM:** 以下の開発タスクを作成してよいですか？

| タスク | 工数 | 優先度 |
|--------|------|--------|
| [タスク1] | [時間] | [高/中/低] |
| [タスク2] | [時間] | [高/中/低] |

**合計工数:** [時間]
```

## 回答フォーマット（全体）

```
## 要件レビュー: [要件名]

### 要件の確認

**概要:** [説明]
**対象ペルソナ:** [リスト]
**ユーザーストーリー:** [ストーリー]

### PMの説明

**背景:** [なぜこの機能が必要か]
**期待効果:** [解決したいこと]
**優先度:** [高/中/低] - [理由]

### CTOの技術レビュー

**実現性:** [可能/要検討/困難]
**工数見積もり:** [合計時間]
**リスク:** [リスクリスト]
**推奨アプローチ:** [実装方針]

### PM・CTO協議

**議論ポイント:**
- [議論1]

**合意事項:**
- [合意1]

### 開発タスク

| # | タスク | 概要 | ファイル | 工数 | 依存 |
|---|--------|------|----------|------|------|
| 1 | [名前] | [説明] | [ファイル] | [時間] | - |
| 2 | [名前] | [説明] | [ファイル] | [時間] | #1 |

### 大株主への確認

これらのタスクをBeadsに登録し、Linearに同期してよいですか？

**合計工数:** [時間]

---

**承認後の次ステップ:**
1. `bd create`でBeadsタスク作成
2. Linear同期スクリプトでLinearに登録
3. 開発セッションで実装開始
```

## タスク作成テンプレート

承認後、以下の形式でタスクを作成します：

```bash
bd create "[タスク名]" --description "[詳細説明]

対象ファイル:
- [ファイルパス1]
- [ファイルパス2]

変更内容:
- [変更1]
- [変更2]

受け入れ条件:
- [条件1]
- [条件2]

依存: [依存タスクID（あれば）]"
```

## 注意事項

1. **要件は変更しない** - 技術的制約で調整が必要な場合は`/meeting:product`に戻る
2. **工数は正直に** - 楽観的な見積もりは避ける
3. **タスクは具体的に** - ファイルパス、変更内容を明確に
4. **依存関係を明示** - ブロッカーになるタスクを特定
