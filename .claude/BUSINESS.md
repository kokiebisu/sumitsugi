# tsumugi - ビジネスロジック・オペレーション

**最終更新日**: 2026-02-05
**対応バージョン**: REQUIREMENTS.md v3.0

## 用語について

**UI表示用語：**

- 前の住人：暮らしを譲る側のユーザー
- 次の住人：暮らしを引き継ぐ側のユーザー

**内部用語（コード・データ構造）：**

- `seller`：前の住人（内部用語）
- `isSeller`：セラーフラグ
- `sellerProfile`：セラープロフィール

**重要：** セラー登録済みのユーザーも、他の物件では次の住人として活動できる。「前の住人」「次の住人」はロールであり、固定的な分類ではない。

## ビジネスモデル概要

### 基本的な仕組み

tsumugiは、前の住人が作り上げた暮らしを次の住人へ引き継ぐプラットフォームです。

**取引の流れ：**

1. 前の住人（譲渡側）が物件情報を登録
2. 次の住人（引き継ぎ側）が物件を閲覧・内見
3. 引き継ぎ相談・契約
4. 引越し費用の支払い
5. 引き継ぎ実施
6. 契約期間（1〜6ヶ月）の居住
7. 次の人へ引き継ぐ or 退去

## 物件のステータス管理

### ステータスの種類

```typescript
status: 'draft' | 'public';
```

- **draft**: 下書き状態。まだ公開されておらず、一覧には表示されない
- **public**: 公開状態。物件一覧に表示され、誰でも閲覧可能

### ステータス遷移

```
新規作成 → draft → (前の住人が公開) → public
                  ← (非公開に戻す) ←
```

## 引き継ぎフロー

物件の引き継ぎは以下の7ステップで行われる：

### 1. 物件登録・公開（前の住人側）

前の住人が以下の情報を登録：

- 基本情報（タイトル、写真）
- 引き継いでもらう家具
- 物件詳細（間取りなど）
- エリア情報

**大家承認について：**

- 物件登録時に大家承認は必須ではない（`landlordConsent: false`でも公開可能）
- 大家承認済みの物件（`landlordConsent: true`）には「✓ 大家承認済み」バッジが表示される
- 問い合わせを受けた後、具体的な入居希望者がいる状態で大家に相談することも可能

### 2. 問い合わせ（次の住人側）

次の住人が：

- 物件一覧から気になる物件を探す
- 詳細ページで情報を確認
- 「引き継ぎを相談する」から問い合わせ
- 内見希望日程を伝える

**問い合わせステータス：**

- `pending`: 未対応（新規問い合わせ）
- `reviewing`: 確認中（前の住人が内容確認中）
- `approved`: 承認済み（内見可能、日程調整待ち）
- `viewing_scheduled`: 内見予約済み（日時確定）
- `contract_in_progress`: 契約手続き中
- `completed`: 完了（契約成立、引き継ぎ完了）
- `rejected`: お断り（前の住人側が辞退）
- `cancelled`: キャンセル（申込者都合でキャンセル）

### 3. 大家承認取得（任意）

- 問い合わせ後、必要に応じて大家に相談・承認取得
- 既に承認済みの場合はスキップ

### 4. 内見調整・実施

- 内見日程の調整
- 実際の物件見学
- 家具・インテリアの状態確認
- 引き継ぎ条件の確認

### 5. 契約・支払い

#### 5.1 申込金支払い（¥20,000）

内見後、賃貸審査申し込み時：

- **申込金**: ¥20,000（固定額、非返金）
- **即座に前の住人へ送金**: Stripe Transfer
- **目的**: 前の住人の機会損失補償、次の住人のコミットメント確保

#### 5.2 賃貸契約締結

賃貸審査通過後：

- 大家・管理会社と賃貸借契約を直接締結
- 引き継ぎ日程をプラットフォーム上で確定（必須）

#### 5.3 デポジット支払い（30%）

賃貸契約締結後：

- **金額**: 引越し費用の30%（最低¥30,000、最高¥50,000）
- **保管**: Stripe Connect でエスクロー保管
- **返金**: キャンセルポリシーに基づく

#### 5.4 残額支払い（70%）

引き継ぎ日確定時：

- **金額**: 引越し費用の70%
- **保管**: Stripe Connect でエスクロー保管
- **トリガー**: 引き継ぎ日がプラットフォーム上で確定された時点で自動請求

**引越し費用の構成（ユーザーには一括表示）:**

- 追加清掃費（¥8,000固定）
- 前の住人への支払い
- 大家協力金（引越し費用の1%、最低保証¥3,000）
- プラットフォーム手数料（15%）

**引越し費用のフルコスト分配（¥100,000の場合）:**

| 宛先                     | 金額                     | 性質                   |
| ------------------------ | ------------------------ | ---------------------- |
| 前の住人                 | ¥74,000                  | 家具・暮らしの対価     |
| tsumugi                  | ¥15,000（15%）           | プラットフォーム手数料 |
| 清掃業者（管理会社経由） | ¥8,000                   | 家具の追加クリーニング |
| 大家                     | ¥3,000（1%、最低¥3,000） | 協力金                 |

※ 紹介フィー¥3,000/成約はtsumugiの手数料から支出（Phase A）

**追加清掃費と敷金クリーニングの関係:**

追加清掃費¥8,000は敷金クリーニングとは**別物**:

| 項目            | 敷金クリーニング                               | tsumugi追加清掃費              |
| --------------- | ---------------------------------------------- | ------------------------------ |
| 目的            | 部屋の原状回復                                 | 残置家具のクリーニング         |
| 対象            | 壁、床、水回り、エアコン                       | 家具表面、布製品消臭、家電     |
| 費用負担        | 前の住人（敷金から）                           | 次の住人（引越し費用から）     |
| 発注元          | 管理会社                                       | 管理会社（既存業者に追加依頼） |
| tsumugi関与なし | tsumugiチェックリスト（F-613）で作業内容を共有 |

Phase 1では管理会社の既存クリーニング業者が部屋清掃の延長として家具清掃を実施する方針。tsumugiが別途業者を手配する必要はない。

**注意: ¥8,000および作業内容はPhase 1の初期案件で実地検証して確定する。** 最初の数件で管理会社の業者に「家具もお願いできるか」を確認し、対応可能な範囲と適正価格を把握してから正式仕様化する。布製品（ソファ、マットレス等）の本格洗浄は既存業者では対応困難な場合があり、簡易消臭の範囲で提供するか専門業者を別途手配するかは実地検証後に判断。

**Phase 2検討事項: 清掃費負担者選択モデル**

将来的に、清掃費¥8,000の負担者を前の住人が選べるオプションを検討:

- 前の住人が負担 → 表示価格が安くなり成約率UP、「プロ清掃済み」バッジ
- 次の住人が負担 → 現状モデル（引越し費用に含む）
- 全物件プロ清掃必須は維持（tsumugiブランド）

**決済システムの詳細**: [決済システム設計書](../docs/plans/2026-01-31-payment-system-design.md)

### 6. 引き継ぎ実施

#### 6.1 引き継ぎ作業

- 鍵の受け渡し
- 家具・インテリアの使い方説明
- 近隣情報の共有
- 植物の世話方法など、個別事項の引き継ぎ

#### 6.2 引き継ぎ完了確認

- 双方がプラットフォーム上で「引き継ぎ完了」ボタンを押下
- 24-48時間の異議申し立て期間

#### 6.3 エスクロー解放・自動分配

異議申し立てなく24-48時間経過後：

- Stripe Connect から自動分配
- 前の住人へ支払い
- 大家へ協力金送金
- 管理会社へ追加清掃費送金
- プラットフォーム手数料

### 7. 次の引き継ぎ or 退去

- 次の人へ引き継ぐ場合：同じフローを繰り返す（セラー登録が必要）
- 退去する場合：家具を持ち出す or 処分

**重要：** セラー登録済みのユーザーも、他の物件では次の住人として暮らしを引き継ぐことができる。「前の住人」「次の住人」はロールであり、ユーザーの固定的な分類ではない。

## 戦略・UX設計

### 家具引き継ぎの掲載戦略

**結論: ハイブリッド型（あらかじめ出品時に載せて、詳細は現地で）**

#### なぜあらかじめ載せるべきか

入居希望者にとって「家具が引き継げる」ことは、引っ越し費用の節約という大きな**「応募の動機」**になる。特に大型家具（冷蔵庫、洗濯機、ベッドフレーム、サイズぴったりの棚など）が最初から分かっていると、マッチング率が格段に上がる。

#### その場での交渉の役割

出品時に漏れていた小物や、「実はこれも……」という相談は内見時に発生する。

#### 実装方針

- 出品項目には「引き継ぎ可能リスト」を設け、写真付きで掲載
- トラブル防止のため「状態や最終的な譲渡の有無は内見時に合意すること」と注釈を入れる

### マッチング成立の定義

**マッチング成立 ＝ 「入居の意思（申し込み）」と「現入居者の承諾」が一致した時**

#### 賃貸契約締結（判をついた時）ではない理由

賃貸契約成立までのタイムラグが長すぎて、家具の処分や引っ越し準備が間に合わなくなるため。

#### アプリ上の扱い

「この人に譲る／この部屋に住む」という合意が取れた段階を「マッチング（予約状態）」とし、その後の入居審査を経て「賃貸契約」へと進む二段構えとする。

### 「引き継ぎ可能期間」の扱い

**結論: 項目として残し、「退去（引き渡し）希望時期」として扱う**

#### 管理会社の清掃期間が不確定な理由

管理会社の清掃・点検スケジュールは事前確定が困難。しかし、目安がないとスケジュールマッチングができない。

#### なぜ消さない方がいいのか

入居希望者は「今の家をいつ出るか」を逆算して探している。「何月下旬頃に引き継ぎたい」という現入居者の希望時期がないと、スケジュールが合うかどうかが判断できず、内見自体を諦めてしまう。

#### 実装方針

- 項目名: 「退去（引き渡し）希望時期」（「引き継ぎ可能期間」ではない）
- 定型文を自動挿入: 「※実際の入居日は管理会社の清掃・点検スケジュールにより前後する場合があります」
- これにより、管理会社との矛盾を防ぐ

## プラットフォーム信頼性の強化

ユーザーの善意（申告）だけに頼らず、プラットフォームを通すメリットを設計する必要があります。

### 1. 交渉のトラッキング仕組み化

**譲渡合意フォーム（内見後ボタン）：**

- 内見が終わったタイミングで、アプリが双方に「内見お疲れ様でした！引き継ぐ家具は決まりましたか？」とプッシュ通知を送る
- 前の住人：「冷蔵庫を0円、棚を3,000円で譲る」と入力
- 次の住人：それをアプリ上で「承認」

**「合意書」の自動生成：**

- アプリ上で金額や品目を確定させることで、万が一「入居したら壊れていた」「やっぱり持っていかれた」というトラブルが起きた際の**法的なエビデンス（合意書）**を自動発行する
- ユーザーへのメリット：「自分たちで約束するより、アプリを通したほうが安心」と思わせる

### 2. 家具代金の決済をプラットフォームで持つ

**アプリ内決済の導入：**

- 家具の代金を現金で手渡しさせるのではなく、メルカリのようにアプリ内で決済（クレジットカード等）させる
- 運営側のメリット：確実に内容を把握でき、手数料を取ることも可能
- ユーザーのメリット：知らない人に現金を見せたり、大金を持ち歩く必要がない

### 3. 管理会社との連携（残置物同意の自動化）

**残置物リストの連動：**

- 内見時に決まった家具リストを、そのまま管理会社へ「残置物同意書」として自動転送する仕組み
- 賃貸物件では、本来「家具を置いていくこと」は契約違反（原状回復義務違反）になる
- 「tsumugiのアプリで合意されたものだけは、管理会社も特別に許可する」というルールにすれば、ユーザーは怒られないために必ずアプリに入力するようになる

## 内見後フロー詳細仕様（ブラッシュアップ案）

### 背景と課題

従来の引き継ぎフローでは、内見から契約までのタイムラグが長く、以下の問題が発生していました：

- 現住人が「捨てなくていいのか」不安なまま待機
- 他の人に取られる心配がある
- 管理会社への連絡が遅れて清掃業者が家具を処分してしまうリスク

このブラッシュアップ案は、これらの課題を解決し、スムーズな引き継ぎを実現するための詳細フローです。

### フロー概要（二段構え方式）

**ステップ1（Web上・スピード重視）:** ユーザー同士の「約束」を確定

**ステップ2（書類・正確性重視）:** 法的な「エビデンス」に昇華してプロに届ける

### 詳細ステップ

#### 1. 内見直後：現住人が「最終リスト」を登録

**タイミング:** 内見終了後、できるだけ早く

**アクション:**

- 内見で話した内容に基づき、現住人がWebプラットフォーム上で「これとこれを譲ります」と確定
- 具体的な家具リスト、状態、金額（ある場合）を入力

**システム動作:**

- 最終リストの入力フォーム（Web）
- 写真アップロード機能（状態記録のため）
- 金額入力（無償の場合は0円）

#### 2. 即時：新住人がWeb上で「受諾」

**タイミング:** リスト登録直後（または内見後24時間以内）

**アクション:**

- 新住人にメール通知
- Web上でリスト内容を確認して「受諾」ボタンをクリック

**システム動作:**

- メール通知の送信（リンク付き）
- リスト内容の表示（家具、状態、金額）
- 受諾/辞退ボタンの表示

**効果:**

- ここで一度「マッチング（仮）」が成立
- 現住人は「捨てなくていいんだ」と安心
- 他の人に取られる心配がなくなる

#### 3. 契約フェーズ：残置物同意付きの「入居申込・契約」

**タイミング:** 受諾後、賃貸借契約の締結前

**アクション:**

- tsumugi側で「残置物合意書（兼 賃貸借契約の特約）」を自動生成

**合意書の内容:**

- リストにある家具は現住人から譲渡されたものであることを明記
- 故障等の責任は大家・管理会社に問わない（現状有姿）
- 将来の退去時には新住人が責任を持って処分することを約束
- 家具の状態（写真付き）
- 譲渡金額（ある場合）

**システム動作:**

- リストデータを元に合意書を自動生成（PDF）
- Web上で新住人が内容を確認
- デジタル署名（電子署名またはチェックボックス同意）

#### 4. 最終完了：大家・管理会社へ届く

**タイミング:** 新住人が署名を完了した後

**アクション:**

- 合意書が管理会社（または大家）へ自動送信（メールまたはシステム連携）

**送信内容:**

- 残置物合意書（新住人署名済み）
- 家具リスト（写真付き）
- 引き継ぎスケジュール

**管理会社側の対応:**

- 「清掃業者への『捨てないで指示』」を確定
- 残置物の最終チェック
- 設備点検時に家具の状態も確認

### 大家・管理会社への報告フロー

**基本方針:** 管理会社が窓口となり、大家への報告は管理会社経由で行う

**理由:**

- 一般的に管理会社が「清掃・管理の責任者」
- 現場の負担が少ない
- 大家さんには事後報告（または月次レポート）で十分

**報告内容:**

- 「次の入居者が決まり、一部家具を引き継ぐ予定です」
- 残置物リスト（写真付き）
- 新入居者の合意書（署名済み）

### この方式のメリット

**1. スピード感**

- 内見の熱が冷めないうちにマッチング確定
- 修正が必要な場合も柔軟に対応可能（Web上で完結）

**2. 安心感**

- 現住人：「捨てなくていい」が確定
- 新住人：「他の人に取られない」が確定
- 管理会社：「新入居者が責任を持つ」というエビデンスがある

**3. 法的エビデンス**

- トラブル時の証拠書類として機能
- 管理会社も安心して鍵を渡せる

**4. トラブル防止**

- 「言った・言わない」を防ぐ
- 清掃業者の誤処分を防ぐ
- 退去時の責任所在が明確

### 今後の検討事項

#### 残置物合意書の文言詳細

トラブルを未然に防ぐための「魔法の文言（免責事項など）」の作成が必要です。

**検討ポイント:**

- 故障時の責任範囲
- 退去時の処分義務
- 譲渡後の所有権の移転
- 大家・管理会社の免責範囲
- 現状有姿での譲渡であることの明記

#### システム実装の優先順位（Phase 2）

Web アプリケーションとして以下の機能を検討：

- 最終リスト登録フォーム（写真アップロード含む）
- メール通知システム（受諾リンク付き）
- 残置物合意書の自動生成機能（PDF）
- 電子署名/同意機能（Web上で完結）
- 管理会社への自動送信機能（メールまたはAPI連携）

**技術的検討:**

- PDF生成ライブラリ（例：jsPDF, PDFKit）
- 電子署名API（例：DocuSign, HelloSign）または簡易的なチェックボックス同意
- メール送信（SendGrid, AWS SES など）
- ファイルストレージ（合意書PDF保存用）

## データモデル

### Property（物件）必須項目

- `id`: 物件ID（ユニーク）
- `title`: 物件タイトル
- `images`: 写真配列（最低1枚）
- `status`: ステータス（`draft` | `public`）
- `landlordConsent`: 大家承認済みフラグ（boolean）

### Property（物件）オプション項目

- `handoverFee`: 引越し費用（number）
- `rent`: 月額家賃（number）
- `area`: エリア（string、例：「東京」）
- `location`: 位置情報（オブジェクト）
  - `lat`: 緯度
  - `lng`: 経度
  - `neighborhood`: 町名（例：「目黒区中目黒」）
- `layout`: 間取り（例：「1K」「1LDK」）
- `furniture`: 引き継ぎ対象の大型家具（配列）
- `handoverSeller`: 引き継ぎ側プロフィール（オブジェクト）
  - `name`: 名前
  - `occupation`: 職業
  - `avatar`: プロフィール画像

### UserListing（ユーザー作成リスティング）

- `id`: リスティングID

## トラブル対応

### よくあるトラブルと対処法

#### 1. 引越し費用の金額交渉

- 原則：前の住人が設定した金額を尊重
- 交渉可能な範囲：±10%程度
- 著しく高額 or 低額の場合：運営が介入

#### 2. 家具・インテリアの破損

- 引き継ぎ時に状態を写真で記録
- 軽微な破損：次の引き継ぎ料金から減額
- 重大な破損：保険or実費で弁償

#### 3. 引き継ぎのキャンセル

- **前の住人側都合**：引越し費用の全額返金
- **引き継ぎ側都合**：キャンセル料（金額の20%）
- 内見前のキャンセル：無料

#### 4. 賃貸契約上のトラブル

- 大家・管理会社との調整は引き継ぎ側の責任
- 名義変更が難しい場合：tsumugiが仲介サポート

## 緊急退去対策

### 背景と課題

前の住人がtsumugiで物件をリスティングしても、退去日までに次の住人が見つからない場合、家具を全て持ち出す必要がある。tsumugiを使った意味がなくなるという最悪の体験を防ぐための対策。

### 基本方針

「セーフティネットを後から張る」より「**最初から期待値を調整し、正直に伝える**」アプローチを採用。

### 出品ルール

- **退去1ヶ月未満**: 出品不可（エラー表示）
- **退去1-2ヶ月**: 警告付きで出品可（「残り時間が限られています」）
- **退去2ヶ月以上**: 通常出品

### 段階的通知スケジュール

| 残り時間    | 通知内容                                           |
| ----------- | -------------------------------------------------- |
| **2ヶ月前** | 「順調ですか？価格の見直しも検討してみてください」 |
| **1ヶ月前** | 「処分も並行して検討することをお勧めします」       |
| **2週間前** | 「処分業者の手配を始めましょう」                   |
| **1週間前** | 「緊急引き取りサービスを利用しますか？」           |

### 「即入居可能」ラベル

退去30日以内の物件に自動バッジを表示。「緊急」ではなく「即入居可能」とポジティブにリフレーミング。

- 前の住人視点: 見つかる確率が上がる
- 次の住人視点: すぐ入居できる物件として訴求
- 仲介会社視点: 「すぐ入居したい」客に紹介しやすい

### 最終手段（間に合わなかった場合）

```
Step 1: 退去日延長交渉（ガイド+テンプレ提供）
Step 2: 「即入居可能」ラベルでマッチング加速
Step 3: それでも決まらない場合
        ├─ [A] 緊急引き取りサービス（提携業者が有料で引き取り）
        ├─ [B] 寄付/処分代行（NPO寄付 or 処分）
        └─ [C] 自分で対応（業者情報の提供のみ）
```

Phase 1では「案内 + 手動対応」。需要を検証してからPhase 2で自動化。

## 法律・コンプライアンス

### 宅建業法への対応

#### なぜ宅建免許が不要なのか：法的根拠

**1. 出品（掲載）= 個人間の情報共有**

「案内」や「情報掲載」だけなら、免許のない個人が行っても違法ではありません。

- メルカリで自分の持ち物を出品するのと同じ感覚
- 「この部屋を気に入ってくれる人に譲りたい」という情報をプラットフォームに載せること
- 商売（業）としての「仲介」には当たらない

**2. 案内（内見）= 住み心地の情報提供**

宅建業法で制限されているのは、あくまで「**契約の成立に向けて、法的なアドバイスをしたり契約をまとめたりすること（媒介）**」です。

- 「ここは日当たりがいいですよ」「スーパーが近くて便利ですよ」と、実際の住み心地を伝えるだけなら、それは「案内」であって「法的実務」ではない
- したがって、**免許は不要**

#### 現入居者が案内することの価値

不動産屋の営業マンが案内するよりも、tsumugiの仕組みでは「今住んでいる人」が案内することに価値を置いています。

**リアルな情報:**

- 「冬は少し冷える」「夜の騒音はこれくらい」といった、住んでいる人にしかわからない本音が聞ける

**家具の引き継ぎ:**

- 「この棚、サイズぴったりなので安く譲りましょうか？」といった交渉が、その場で成立する
- これがtsumugiの醍醐味

#### 役割分担：誰が何をするのか

| 役割                         | 担当者                 | 業務内容                                                     |
| ---------------------------- | ---------------------- | ------------------------------------------------------------ |
| **広報担当・ツアーガイド**   | 現入居者（前の住人）   | 物件情報の掲載、内見時の案内、住み心地の共有、家具の売買交渉 |
| **プラットフォーム（場所）** | tsumugi                | マッチングの場を提供、決済システム、トラブルサポート         |
| **現場監督**                 | 管理会社               | 部屋のクリーニング、残置物の最終チェック、設備点検           |
| **法的な審判**               | 不動産会社（宅建業者） | 賃貸借契約の締結、重要事項説明、法的手続き                   |

#### 基本方針：マッチング vs 仲介の明確な役割分担

tsumugiは宅建業法に抵触しないよう、以下の役割分担を徹底します：

**tsumugiの役割（マッチング）:**

- 物件情報の掲示（掲示板のような情報提供）
- 前の住人と次の住人の引き合わせ
- 「出会いの場」の提供のみ

**宅建免許業者の役割（契約実務）:**

- 重要事項説明（宅建士による）
- 賃貸借契約の締結
- 契約書の作成・捺印
- 法的責任の保証

#### 違法性の回避ポイント

| 項目           | tsumugiの実態                              | 宅建業法対応                                     |
| -------------- | ------------------------------------------ | ------------------------------------------------ |
| マッチング     | アプリ上で希望者を見つける                 | 掲示板や広告と同じ扱い（紹介のみ、仲介ではない） |
| 重要事項説明   | 実施しない → 宅建士が必ず行う              | 資格者が対面またはIT重説で実行                   |
| 契約書の作成   | 作成しない → 免許業者が作成                | 闇取引ではなく、正規の賃貸借契約として成立       |
| 管理会社の介入 | 退去者と入居者の間で設備チェック・清掃手配 | 消費者（借主）の保護を担保                       |

#### 規制対象となる行為（tsumugiでは行わない）

宅建業法で規制されているのは「免許のない者が反復継続して不動産取引の媒介（仲介）や代理を行うこと」です。

**tsumugiが行わないこと:**

- 賃貸借契約の締結代行
- 重要事項の説明
- 契約条件の交渉代理
- 手付金・敷金の預かり

#### 提携不動産会社との連携フロー

**マッチング成立後の流れ:**

1. **マッチング成立（tsumugi）**
   - 現入居者と新入居者が「ここに決めた！」と合意
   - tsumugiプラットフォーム上で引き継ぎ相談が完了

2. **管理会社の介入**
   - 入居者が入れ替わるタイミングで、管理会社が手配した業者が介入
   - 部屋のクリーニング実施
   - 残置物の最終チェック
   - 設備の動作確認

3. **契約の締結（提携不動産会社）**
   - 最終的な「賃貸借契約」は、不動産のプロ（宅建業者）が仲介に入る
   - 宅建士による重要事項説明
   - 契約書への署名捺印
   - 法的に正しい手続きで契約が結ばれる

#### 家具譲渡の取り扱い

**前入居者からの家具譲渡について:**

- 家具の譲渡は不動産取引ではなく、動産の個人間売買
- 別途「家具譲渡合意書」を作成し、法的トラブルを防止
- 金額・状態・引き渡し条件を明記
- 譲渡後のトラブルは当事者間で解決（tsumugiは仲介のみ）

#### 個人間で完結できる範囲

| 行為                              | 法的位置づけ     | 免許               |
| --------------------------------- | ---------------- | ------------------ |
| ✅ 物件情報の掲載（出品）         | 個人間の情報共有 | 不要               |
| ✅ 内見時の案内（住み心地の共有） | 情報提供         | 不要               |
| ✅ 家具・インテリアの売買交渉     | 動産の個人間売買 | 不要               |
| ❌ 賃貸借契約の締結               | 法的実務（媒介） | **宅建業者が必要** |
| ❌ 重要事項説明                   | 法的実務         | **宅建士が必要**   |

#### 一言でまとめると

**「入り口（集客・マッチング）」は新しく効率的にしているが、「出口（契約）」は法律に則った既存の不動産取引のルールに従う**

これにより、消費者保護を担保しつつ、イノベーティブなサービスを提供できます。

tsumugiは「案内」と「情報掲載」のみを提供し、法的実務は専門家に任せることで、宅建業法の規制を回避しています。

### 個人情報保護

- 前の住人の個人情報は最小限のみ表示
- 連絡先の交換は相談後
- プライバシーポリシーの整備（今後）

### 消費者保護

- 適正な価格設定のガイドライン
- クーリングオフ制度の検討
- トラブル時のサポート体制
