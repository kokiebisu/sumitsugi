# キャンセルポリシー検討メモ

**作成日:** 2026-01-29
**ステータス:** 検討中 → 仕様化待ち

---

## 問題定義

**新住人の自己都合キャンセル時に、現住人（前の住人）が大損するリスク**

### 現状の課題

- 家具引き継ぎの合意後、新住人がキャンセルすると：
  - 現住人は家具を処分できず、引越しできない
  - 処分費用が想定外に発生
  - 引越し時期がずれ込み、賃貸契約上の問題が発生する可能性

---

## 提案ソリューション

### 違約金制度の導入

> 「家具引き継ぎの合意をした後、新住人の都合でキャンセルした場合は、現住人の家具処分費用として〇〇円を違約金として徴収します」

**メリット:**

- 現住人の金銭的損失を補償
- 新住人の安易なキャンセルを抑止

**検討が必要な点:**

- 違約金額の設定根拠（家具処分費用の実態調査）
- 支払い方法・タイミング
- 法的な妥当性（消費者契約法との整合性）

---

## 詳細検討項目

### 1. キャンセルのタイミング定義

どの時点から「キャンセルペナルティ対象」とするか？

| タイミング                   | ペナルティ | 理由                               |
| ---------------------------- | ---------- | ---------------------------------- |
| 物件閲覧・問い合わせのみ     | なし       | まだ合意していない                 |
| 引き継ぎ申込み               | ？         | 検討が必要                         |
| **引き継ぎ合意（契約成立）** | **あり**   | 現住人が処分を見送る判断をしている |
| 引越し1週間前                | より高額？ | 現住人の損失が確定的               |

### 2. 違約金額の設定

**一律方式 vs 変動方式**

**A. 一律方式（シンプル）**

- 例: 一律3万円
- メリット: わかりやすい、運用が簡単
- デメリット: 物件や家具の価値に関係なく一律

**B. 変動方式（公平性重視）**

- 例: 引越し費用（家具引き継ぎ料）の50%
- メリット: 物件規模に応じた補償
- デメリット: 計算が複雑

**C. 段階的方式**

```
- 合意後7日以内: 引越し費用の30%
- 7日～14日: 引越し費用の50%
- 14日以降: 引越し費用の100%
```

### 3. 例外ケース

ペナルティを免除する正当な理由は？

- 天災・不可抗力
- 物件側の重大な瑕疵発覚
- 現住人の契約違反
- 病気・入院など（要証明書）

### 4. 支払い方法

- エスクロー（事前にsumitsugiが預かる）
- クレジットカード決済
- 銀行振込

### 5. 法的側面

**消費者契約法との整合性**

- 違約金が「平均的な損害額」を超えないこと
- 家具処分費用の実態データが必要
  - 例: 1K/1DK → 平均3～5万円
  - 例: 2LDK → 平均8～15万円

**特定商取引法（クーリングオフ）**

- オンライン契約でのクーリングオフ期間（8日間）との関係
- クーリングオフ期間内はペナルティなしとする必要があるか？

## 現住人側のキャンセルは？

**逆のケース: 現住人が引き継ぎ合意後にキャンセルした場合**

- 新住人は引越し準備をしている可能性
- 引越し業者のキャンセル料が発生している可能性
- → 同様にペナルティが必要

**バランスの取れた設計:**

- 双方向のキャンセルペナルティ
- 金額は同等（公平性）

## 次のステップ

### 優先度: 高

1. **市場調査**
   - 家具処分費用の実態（業者見積もり）
   - 他社（Airbnb、賃貸サービス）のキャンセルポリシー

2. **法的レビュー**
   - 弁護士による消費者契約法チェック
   - 利用規約ドラフト作成

3. **金額設定**
   - データに基づく違約金額の決定
   - 段階的方式 vs 一律方式の決定

4. **仕様化**
   - `.claude/BUSINESS.md` への反映
   - UIフロー設計（キャンセル画面での警告表示）
   - データモデル設計（Cancellationテーブル）

### 優先度: 中

5. **エスクロー機能の実装検討**
   - 引越し費用を事前預かり
   - キャンセル時に自動で違約金徴収

6. **紛争解決プロセス**
   - 不当なキャンセル申告があった場合の対応
   - サポート体制の整備

- 最初のMVPでは**シンプルな一律方式**から始めるのが現実的
- 段階的に精緻化していく
- ユーザーテストで「納得感」を確認することが重要
- キャンセル率のデータ取得後、必要に応じて制度を見直し
